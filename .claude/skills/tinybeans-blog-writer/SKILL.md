# tinybeans ブログ執筆スキル

tinybeans.net のブログ記事を、親しみやすく読者に語りかけるスタイルで執筆するためのスキルです。

## When to Use This Skill

- ブログ記事を新規作成するとき
- 技術記事のドラフトを書くとき
- tinybeans.net 向けのコンテンツを作成するとき
- 日本語の技術ブログを執筆するとき

## 文体の基本ルール

### 1. 親しみやすく話しかけるような口調

読者に直接語りかけるトーンを使用する：

- 「〜ですね」「〜しましょう」「〜ですよ」などの語尾
- 「さて、みなさん」「こんにちは」などの挨拶
- 「〜ましたか？」「〜思いませんか？」などの問いかけ

### 2. 丁寧語を基本とした敬体

- 「です・ます」調で統一
- 堅苦しくない、親しみやすい敬語を使用
- 過度にフォーマルな表現は避ける

### 3. 適度にカジュアルな表現

- 感嘆符「！」を適度に使用して感情を表現
- 「（？）」「（笑）」などの挿入も可
- くだけた表現も適度に使用

### 4. 対話的な構造

- 想定される読者の疑問に答える形式
- 読者の心の声を代弁し、それに応答する展開
- 「〜しても良いですが」「〜がおすすめです」など、提案型の表現

### 5. 適度な感情表現

- 「素晴らしい」「嬉しい限り」「心強い」など、感情を込めた表現を使用
- ただし過度な感情表現は避ける
- 自然で誠実な感情表現を心がける

## 記事構成のルール

### 1. 導入部分

- 記事の目的を冒頭で明確に提示
- イベント参加（Advent Calendar など）は冒頭で明記
- 「今日は〜をご紹介します」のような宣言で始める

### 2. 見出しの構造

- 階層的な見出し（##、###）を適切に使用
- 見出しは簡潔で分かりやすく
- 「〜とは」「〜のいいところ」「〜の作り方」など、明確な見出し
- 必要に応じて番号付きリスト（1. 2. 3.）を使用

### 3. 手順説明の構造（技術記事の場合）

- ステップバイステップで丁寧に説明
- コードブロックを適切に使用（言語指定を忘れずに）
- 実行結果やコマンド出力の例示
- 注意点や補足説明を適切に配置

### 4. 箇条書きの活用

- 重要なポイントを箇条書きで列挙
- 見やすく整理された情報提示

### 5. 画像の挿入

- スクリーンショットを適切に配置
- Markdown の標準記法で挿入
- 画像の説明は分かりやすく

### 6. 外部リンクの参照

- 公式ドキュメントやツールへのリンクを適切に配置
- リンクテキストは分かりやすく
- 参考資料として箇条書きでリストアップすることも

### 7. 結論・まとめ

- 記事の最後に総括を配置
- 「以上となります」「まとめ」などで締めくくる
- 読者への呼びかけや今後の展望を含めることも

## 表現の特徴

### 1. 技術用語と日本語のバランス

- 技術用語は基本的に英語のまま使用（Docker、DDEV、Composer など）
- 必要に応じて日本語の説明を併記
- 初出時に簡単な説明を加えることが望ましい

### 2. 読者への配慮

- 読者を励ます表現を使用
- 警告や注意点は明確に記載
- 安心感を提供する表現を適度に入れる

### 3. 比喩や例えの使用

- 分かりやすい例えや比喩を使用
- 技術的な内容を身近な例で説明

### 4. 個人的な経験の共有

- 個人的な視点を交える
- 実例や実績を具体的に挙げる

### 5. ユーモアの使用

- 適度なユーモアを交える
- 堅苦しくならないよう、軽妙な表現を適度に使用

### 6. 打ち消し線や補足の使用

- 情報の更新を示す際に打ち消し線を使用

## 避けるべき表現

### 絶対に避けるもの

1. **過度にフォーマルな表現**
   - 堅苦しい文語調
   - ビジネス文書的な硬い表現
   - 「〜である」調

2. **一方的な主張**
   - 「〜すべき」「〜しなければならない」などの強い命令形
   - 読者に選択肢を与えない表現

3. **否定的・攻撃的な表現**
   - 他のツールやCMSを貶めるような表現
   - 比較する際は公平で建設的な視点を保つ

4. **専門用語の乱用**
   - 説明なしの専門用語の連続
   - 読者の理解を助ける配慮の欠如

5. **過度な装飾**
   - 絵文字の多用（文中には基本的に使用しない）
   - 過度な強調（太字、イタリックの乱用）

6. **曖昧な表現**
   - 「たぶん」「おそらく」などの不確実な表現の乱用
   - 不確実な場合は明確にその旨を記載する

## 特殊なケース

### 更新情報の記載

過去の記事を更新した場合、記事の最後にその旨を記載する。

### 宣伝・商用コンテンツの扱い

自社製品やサービスを紹介する際は、「（宣伝）」と明記して透明性を保つ。

### コミュニティへの言及

人名やコミュニティを言及する際は、敬意を持って記載する。

## AI Assistant Instructions

このスキルが起動されたら、以下のルールに従って記事を執筆してください。

### 必ず守ること

1. **です・ます調で統一する**
2. **読者に語りかけるトーンを維持する**
3. **技術用語は英語のまま、初出時に説明を加える**
4. **見出しは階層的で分かりやすく構成する**
5. **コードブロックには言語を指定する**
6. **他のツールやサービスへの言及は公平に**

### 絶対に避けること

1. **「〜である」調を使わない**
2. **絵文字を文中に使わない**
3. **強い命令形（〜すべき、〜しなければならない）を使わない**
4. **他のツールを貶める表現を使わない**

### 例文の使用に関する重要な注意

**このスキルに記載されている例文はあくまで参考です。例文をそのまま、または頻繁に使用しないでください。**

AIは例として提示された文言を過度に使用する傾向があります。以下の点に注意してください：

- 例文（「今日は〜をご紹介します」「さて、みなさん」「心強いです」「嬉しい限りです」など）は文体の雰囲気を示すためのものです
- 毎回同じフレーズを使うと不自然になります
- 文脈に応じて自然な表現を創造的に生成してください
- 例文のパターンを参考にしつつ、バリエーション豊かな表現を使用してください
- 特に導入部分や締めの表現は、記事のテーマに合わせて都度工夫してください

### 執筆フロー

1. **テーマの確認**: 何について書くか明確にする
2. **構成の決定**: 見出しの階層構造を設計する
3. **導入部の執筆**: 記事の目的を明確に提示
4. **本文の執筆**: ステップバイステップで丁寧に
5. **まとめの執筆**: 総括と読者への呼びかけ
6. **チェック**: 文体の統一性、リンク、コードブロックの確認
